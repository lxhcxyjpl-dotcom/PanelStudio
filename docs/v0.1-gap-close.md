# v0.1 HTTP gap close

Audit of every route in handbook section 10 (the HTTP tables) and in `docs/openapi.json`, compared with `apps/server/src/routes.ts`. Both contracts use the prefix `/api/v1`. The handbook writes `:projectId`; OpenAPI writes `{projectId}`. The route set is the same. There is no path in one list that is absent from the other.

Status is `implemented` when the handler already existed on main, `now implemented` when this change adds it, or `intentionally deferred` when the handbook keeps it out of v0.1.

## What was missing

On main after phase 6, these five routes were in the handbook tables and in OpenAPI, and had no handler:

- `GET /api/v1/projects`
- `DELETE /api/v1/projects/{projectId}`
- `POST /api/v1/projects/{projectId}/restore`
- `GET /api/v1/projects/{projectId}/revisions`
- `GET /api/v1/projects/{projectId}/revisions/{revision}`

`GET /api/v1/projects/{projectId}/assets` existed and always returned every row with `nextCursor: null`, including when `limit` was set. Phase 0 says `limit` is optional, from 1 to 100, and has no default.

## What this change implements

Project list, soft-delete, restore, and revision reads. Asset list paging uses the same cursor rules.

Handbook section 9.1:

- Soft-delete does not delete asset bytes. Original and normalized content still download.
- A deleted project rejects new changes with `PROJECT_DELETED` (409): rename, transactions, undo, redo, uploads, layout, preview, export, and AI layout.
- Unfinished jobs for that project are cancelled. A queued job becomes `cancelled` with a null error, which is the phase 0 cancellation shape. A running provider call is aborted.
- Restore clears `deletedAt`. The stored document, revisions, and undo stacks stay, so undo after restore still works.
- Reading a deleted project, its document, its revisions, and its assets stays allowed. The handbook forbids new changes; it does not hide history.

Deleting a project that is already deleted returns that same row. Restoring a project that is not deleted returns it unchanged. A second restore with the same Idempotency-Key and the same body replays the first response.

`limit` omitted means the whole matching list and `nextCursor: null`. `includeDeleted` omitted means false. An empty cursor is rejected. Cursors are opaque. Projects and assets are ordered by `createdAt`, then `id`, ascending. Revisions are ordered by revision number, ascending. The handbook does not define that order; this is the stable order the pages use.

No new domain command was added.

## Interface

Handbook section 1.2 requires open, soft-delete, and restore. Section 14.3 already places a project menu first in the toolbar. Sections 14–19 do not describe a separate project browser, a trash view, or a confirmation dialog, so those were not added. The existing menu now lists projects (`GET /projects`), soft-deletes the open project, and restores a deleted one. Opening a project still fits the window (section 16.3). A pending save draft blocks the switch and keeps the existing recovery dialog.

## Intentionally deferred

Handbook section 1.3 says these do not enter v0.1. They have no row in the HTTP tables and no OpenAPI path:

- PDF, EPS, and native `.ai` import.
- Editing path nodes of an imported SVG in the browser.
- Reconstructing curves, axes, or text from a screenshot.
- Changing data, axis ranges, or statistics inside a figure.
- General arrows, rich-text callouts, and flowcharts.
- Multiple artboards, collaboration, accounts, and billing.
- Export that converts type to outlines.
- Automatic physical-scale calibration.
- An MCP server, a skill package, and a desktop installer.

Illustrator checks in `docs/illustrator-compatibility.md` stay `needs manual check`. That is a manual acceptance step from handbook section 21.5, not an HTTP route. No release tag was created.
